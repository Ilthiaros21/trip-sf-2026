## Design Context

### Users
Raúl & Pao, two specific people, own trip 25-29 sept 2026 Bay Area. Not public product — personal reference tool. Used pre-trip on desktop while planning, then on phone (Safari iOS for Raúl, Firefox Android for Pao) as offline-ish backup during trip.

### Brand Personality
Calm, precise, trustworthy. Feels like a well-made travel document, not a generic dashboard. Reference: Apple Wallet / Calendar dark mode. Prior artifact (split-flap flight board) sets palette/type precedent — reuse it.

### Aesthetic Direction — REVISED (agency restyle, explicit user override)
Original direction was calm/minimal iOS Wallet-style with glass used sparingly. User explicitly invoked an "Awwwards agency" design skill and, when shown the conflict with this doc, chose to apply it in full anyway (`itinerario.html` / `itinerario-artifact.html`, same session). Current live direction:
- **Ethereal Glass vibe**: deep near-black warm ground (oklch ~0.12L), stronger warm glow orbs (amber/gold, not the cliché purple/cyan), heavier `backdrop-filter: blur()` on header/nav/cards — always with a `@supports` solid-color fallback underneath, never blur-only.
- **Double-bezel cards**: every card (timeline, summary, pretrip) sits in an outer "machined shell" (`.bezel-shell`, padding 5px, radius 28px) wrapping an inner glass core (own bg, inset highlight, radius 20px). Concentric, not flat.
- **Floating island nav**: tab bar is a detached rounded glass pill (inset margin, radius 999px), not an edge-to-edge bar — the one explicit "banned layout" from that skill.
- **Button-in-button**: the expand chevron is never bare — always nested in its own 28px circular pill (`.chevron-wrap`).
- Bento asymmetry only on the Summary tab at ≥720px (varying card spans) — collapses to plain single column on mobile, per that skill's own mobile-override rule. Never applied to the sequential day timelines (wrong content shape for bento).
- Scroll/tab-entry choreography: `riseIn` keyframe (translateY+blur+opacity, GPU-safe transform/opacity/filter only) staggers children on tab activation. Respects `prefers-reduced-motion`.
- **REVISED AGAIN — light, not dark.** User feedback: "todo el framework se ve cero agradable... sensación horrible de oscuridad y el amarillo mostaza me choca." Flipped to a warm light theme, sourced from a 4-color reference palette (Darlington sage `#ACCAB2`, Beeswax amber `#E9A752`, Grenadine orange-red `#D44720`, Cafe Latte brown `#78614D`). `--bg` is now warm cream (oklch 0.965L), `--text` deep Cafe-Latte-brown (oklch 0.3L), `--accent` is Grenadine-derived (oklch 0.55L 0.185C 34H) — no black, no mustard/gold anywhere. Structural stuff (double-bezel, floating nav, glass blur, riseIn motion) untouched — only the color tokens changed. All text/bg pairs re-verified for WCAG AA contrast (≥4.5:1) after the swap using canvas-composited luminance checks, not eyeballed — two tokens (`--text-faint`, the `move` food-tag mix %) needed adjusting because the obvious guess undershot on a saturated warm hue. Single theme still, no OS-driven light/dark toggle — same "commit to one look" pattern as before, just the opposite look now.

- **Moment-card internal layout — "flight-board" restructure** (user: "no me gusta el layout interno" of the timeline cards). Time moved OUT of the thin side spine (which now only shows dot+line) and INTO the card as a big tabular readout on its own top row ("board-line": time + status pill + chevron, one row), with title/location/desc as a full-width row below — title no longer squeezed beside the chevron. Went through the mandatory overdrive propose-3-directions step first; user picked "flight-board scroll reveal" over a boarding-pass/View-Transitions option and a conservative spring-physics-only option. Added `animation-timeline: view()` scroll-driven reveal per card (replaces the old one-shot tab-activation stagger, only in `@supports (animation-timeline: view())` — Firefox has no support as of writing, so it keeps the old JS stagger, a real fallback not a degraded one) plus a quick `rotateX` flap-in on the time digits specifically, calling back to the split-flap board lineage already documented above.

### Aesthetic Direction — REVISED AGAIN (ref1 pastel pivot, explicit user override)
User supplied a reference screenshot ("ref1": soft pastel lavender/periwinkle travel app — white rounded cards, colored rounded time-pill badges, vertical gradient timeline connecting dot-marked events, humanist rounded sans typography) and asked to match it fully, plus called out the display font directly ("parece proyecto de niño chiquito"), asked for higher-quality animations, some liquid glass "wherever you choose," and explicit AI-slop avoidance. This supersedes the Ethereal-Glass/agency-restyle direction above; that history is kept for lineage, not as current guidance.
- **Palette**: warm-neutral pastel lavender ground (`--bg` oklch 0.94L, tinted 280H), white/near-white card surfaces, blue accent (`--accent` oklch 0.55L 0.18C 265H) instead of the prior Grenadine red-orange. Soft radial gradient orbs (blue/amber/pink) in the fixed background instead of the prior single warm glow.
- **Bezel-shell neutralized**: the double-bezel concentric-shell pattern from the agency-restyle era is gone. `.bezel-shell` is now an unstyled wrapper — cards carry their own visual weight via a soft two-layer shadow (`0 1px 2px` contact + `0 10px 24px -12px` ambient) and a 1px border, flat not concentric. Kept the wrapper class only so future structural changes don't require touching every call site.
- **Liquid glass, scoped not gratuitous**: applied only to `.app-bar` (header + mode-switch + tabs nav) — layered `backdrop-filter: blur(30px) saturate(170%)` (mode-switch/tabs use a lighter `blur(18px) saturate(160%)`), a top specular-highlight gradient pseudo-element, and a bottom hairline light-refraction edge. Deliberately NOT applied to content cards — glassmorphism-everywhere is still a banned AI-slop pattern; this is the one exception, chosen because chrome/nav floating over scrolling content is where glass actually reads as functional rather than decorative.
- **Spine gradient**: the timeline's vertical connector line is no longer a flat neutral — `spineColor(index, total)` interpolates in OKLCH across blue→amber→pink per day, purely decorative on the connector only. The confirmed/pending dots stay strictly semantic (green/amber, never touched by the gradient) so status is never ambiguous.
- **Animation quality pass**: card entrance easing tightened (`--ease-spring: cubic-bezier(0.19,1,0.22,1)`), added `filter: blur()` into the entrance keyframes (`riseIn`, `flapReveal`) for a softer materialize instead of a hard pop, `card-body-wrap` uses `grid-template-rows` 0fr→1fr for the expand animation (never animates `height` directly). All motion still GPU-safe (transform/opacity/filter only) and respects `prefers-reduced-motion`.
- **`--confirmed` darkened again**: same green-hue WCAG contrast trap as the previous light-palette phase (see Design Principle 7) — resolved to `oklch(0.4 0.1 155)`.

**Typography pairing — REVISED (two roles, not three):**
- **Display**: swapped Bricolage Grotesque → **Familjen Grotesk** (Google Fonts) for trip title, day headings, card titles. Direct response to "no me gusta la que usamos, parece proyecto de niño chiquito" — picked for a more grown-up, slightly condensed humanist-grotesk character that still isn't a reflex-list font.
- **Body/UI**: swapped `-apple-system` system stack → **Hanken Grotesk** (Google Fonts) for dense text, matching ref1's soft rounded-sans full-page typography rather than mixing a system font with a webfont display face.
- **Mono/data role dropped**: JetBrains Mono removed. Times/seats/dates now use the body font (Hanken Grotesk) with `font-variant-numeric: tabular-nums` on the time-pill specifically — ref1's reference has no distinct monospace data layer, and reintroducing one would fight the softer overall type character.

### Motion system — directional curves (motion-design skill pass)
User asked to run the `motion-design` skill reference against every animation in the app and make them "mucho mejores." Replaced the single reused `--ease-spring` curve with four purpose-specific tokens — `--ease-entrance` (expo-out, big reveals: stagger, flap reveal), `--ease-out` (quart-out, default state changes: hover/select), `--ease-in` (quart-in, exits — accelerates, ~75% of the entrance duration per the skill's exit-timing rule), `--ease-in-out` (toggles that return to their start: chevron rotate, checkbox) — plus a duration scale (`--dur-instant` 120ms press feedback, `--dur-fast` 220ms hover/color, `--dur-base` 300ms toggles, `--dur-layout-in`/`--dur-layout-out` 380/290ms accordion open/close). Fixed a real bug this surfaced: the card accordion's open and close were sharing one symmetric transition with an 80ms reveal delay baked into the *base* rule, so on close the text stayed visible while the row had already collapsed — split into a fast undelayed `--ease-in` close and a slower delayed `--ease-out` open, using the CSS rule that a property's own transition value (not the prior state's) governs the animation to reach it. Also fixed a literal `ease` keyword left on `.check-label` — banned by the skill, replaced with `--ease-out`. Press feedback (buttons, tabs, checklist rows, contact links) dropped from 300–400ms to `--dur-instant` (120ms), matching the skill's "instant feedback" bucket — everything at that speed previously felt sluggish for a simple `:active`.

### Aesthetic Direction — REVISED AGAIN (3D cards + categorical spine, explicit user override)
User asked to: remove the one-line day summary (felt redundant with the cards below it — "la información debe estar en cada una de las tarjetas"), give cards "un poco de 3D," and replace the per-card decorative spine segment with one continuous liquid-glass spine per day that reveals color as you scroll, tied to each card's *category* (vuelo/actividad/comida/etc.) rather than its position in the list.
- **Day summary removed**: `day.note` (the paragraph above each day's timeline) is gone from the Itinerario tab. Any content unique to it (not already restated on a card) moved into that card's own `notes` field instead — e.g. Friday's international-flight margin explanation now lives on the "Salir de casa" card, the Riley Green concert note on Saturday's dinner card. `day.note` still exists (and still renders via the same `.day-note` CSS class) on the four Info práctica panels, where it's a short usage instruction, not a redundant recap — that's a different job, so it stayed.
- **Cards get real depth, not a bigger drop-shadow**: `.card` rests at `perspective(1000px) rotateX(1.5deg)` — a barely-there tilt, not skeuomorphism — and flattens to `rotateX(0deg)` on open or on press (`:has(.card-head:active)`, gated behind `@supports selector(:has(a))` so unsupporting browsers just keep the resting tilt, no breakage). Shadow went from a flat 2-layer drop-shadow to a bevel: an inset top highlight (light catching a raised edge), an inset bottom shade, contact + ambient shadow, and a category-tinted glow (`--cat-glow`, set per-card via `card.style.setProperty` in JS) instead of one generic neutral shadow. `.summary-card` got the same bevel treatment (accent-tinted glow) but without the tilt — reserved for the actual timeline "moment" cards the user was pointing at.
- **Spine rebuilt as one continuous element, colored by category not position**: replaced the old `spineColor(index, total)` positional rainbow-interpolation (removed entirely) with a `cat` field per block (`flight` / `transfer` / `activity` / `food` / `event` / `rest`, each a fixed hue token `--cat-*`). One `.spine` div per day (not one segment per card) spans from the first dot's center to the last, positioned/sized in JS (`layoutSpine`, measured via `getBoundingClientRect` against the real rendered dots — so it tracks actual layout, including open/closed card heights) with a gradient built from each block's category color, blended smoothly across the midpoint between adjacent cards for a "liquid" flow rather than hard bands. The scroll-linked "transparent → color" reveal uses a `--reveal` custom property registered with `@property` (`syntax: '<percentage>'`, `inherits: false`) so it can transition smoothly — updated by a single rAF-throttled `scroll` listener that follows whichever day is currently active (not one listener per day). `ResizeObserver` on each day's `.timeline` recomputes the spine's position/gradient on any layout change — a day tab activating (0→real height), a card opening/closing, or a window resize — one mechanism covers all three. The confirmed/pending semantic color on `.block-dot` is untouched by any of this — the spine is still purely decorative, same as before, just categorical instead of positional (Design Principle 3, unchanged).
  - **No external library used, on purpose**: the user explicitly invited pulling in a library for the scroll-linked color reveal if one was genuinely needed. It wasn't — `ResizeObserver`, `getBoundingClientRect`, `requestAnimationFrame`, and `@property`-registered transitionable custom properties are all native APIs with solid support on Safari iOS 16.4+ and modern Firefox Android, exactly this project's target browsers. Adding GSAP/Framer/etc. would have broken Design Principle 5 (zero external JS deps) for a problem the platform already solves.
  - **CSS fallout from the spine becoming a sibling, not a per-card segment**: `.timeline`'s stagger selectors used to key off `:nth-child(N)` on `.timeline > *`; with `.spine` now occupying child-position 1, that would silently off-by-one every card's stagger delay. Fixed by switching to `:nth-of-type(N)` scoped to `.timeline > .block` — cards render as `<article>`, the spine as `<div>`, so `:nth-of-type` counts only among same-tag siblings and stays correct regardless of what else lives in `.timeline`.
  - **Reveal formula corrected**: the first version computed `pct = (vh - rect.top) / (rect.height + vh)` — an "enters at bottom of viewport, exits at top" formula that baked in `window.innerHeight`, so the same physical scroll distance filled the spine at a different rate depending on screen size. User flagged this directly: the fill should depend on the day's own length, not the viewport. Replaced with `pct = clamp(-rect.top / rect.height * 100, 0, 100)` — purely how far the spine has scrolled past the top of the viewport, as a fraction of its own height, no `vh` term at all. A fixed 8% floor keeps a sliver of color visible at the very top (covering the first dot) before any scrolling happens, instead of starting fully blank.

### UX writing pass — Wallet-terse, real data only
User called out specific filler lines by name ("Hora ya decidida", a paraphrased "Asentarse, cena del hotel blablabla") and asked for Apple-Wallet-style terseness: only real data (times, prices, addresses, named facts), nothing explaining the obvious or narrating mood/reasoning. Went through every block in `TRIP_DATA` and cut anything that wasn't a concrete fact — comparisons to the old Mountain View plan, "why we're doing this" reasoning, mood-setting phrases ("llegan cansados de un vuelo largo"). A side effect: several blocks (`Despertar`, `Segunda actividad — por definir`, etc.) now have no `notes`/`food`/`warn` at all, so `hasBody` is false and they render as flat, non-expandable rows — no chevron, no tap target — which is itself more Wallet-like than a chevron leading to an empty reveal. This is the new bar: before adding `desc`/`notes` to a future block, ask whether it's a fact or a narration; only facts survive.

### Design Principles
1. Reliability over spectacle — this is trip-critical reference info; broken render on real Safari iOS / Firefox Android is worse than a boring one. Every glass/blur effect MUST have a `@supports` fallback; this held even through both restyles.
2. One data source of truth in JS — no duplicated strings between "confirmed" and "pending" content.
3. Confirmed vs pending must be visually unambiguous at a glance (not just a color, since colorblind-safe) — the decorative spine (now categorical, `--cat-*` per block) must never be mistaken for status coloring; status stays on the dot/pill only.
4. No AI-slop tells (no left-border-stripe callouts, no gradient text, no generic icon-over-heading cards, no glassmorphism-everywhere). The ref1 pivot explicitly reinstates "glass only where functional" as a hard rule — liquid glass is confined to `.app-bar` and, as of the spine rebuild, the spine fill itself (a second deliberate, user-requested exception — not a drift back toward glass-everywhere). If asked to tone the aesthetic back down further, this is the current baseline to revert toward, not the agency-restyle one two revisions back.
5. Mobile-first, single file, zero external JS deps, zero build step, zero horizontal scroll. Reach for native browser APIs (ResizeObserver, IntersectionObserver, `@property`, `animation-timeline`) before ever reaching for a library — this held even for a feature (scroll-linked spine color reveal) the user explicitly said could justify one.
6. Two-font system: Familjen Grotesk for display/headings, Hanken Grotesk for body/UI/data. No Inter, no Roboto, no Bricolage Grotesque, no JetBrains Mono anymore — no swapping fonts casually, each swap traces to a documented reason like the ones above.
7. Color changes are not free — any token edit (`--accent`, `--confirmed`, `--pending`, etc.) must be re-checked for WCAG AA contrast against every surface it composites onto, not just eyeballed. OKLCH lightness does not track WCAG relative luminance in any simple way, especially on saturated warm/green hues — verify with actual rendered pixels (canvas readback), not the raw L value. Green hues in particular produce deceptively high measured luminance at moderate L — this has required darkening `--confirmed` twice now, in two unrelated palette iterations.
8. Motion uses directional curves, not one curve for everything — entrances get `--ease-entrance` (expo-out), state changes get `--ease-out` (quart-out), exits get `--ease-in` (quart-in, ~75% of the paired entrance's duration), in-place toggles get `--ease-in-out`. Never write a bare `ease` keyword — banned by the motion-design skill, and it slipped in once already.
